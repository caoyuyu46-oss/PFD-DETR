# Release record

## Implementation and provenance

The distribution starts from the official RT-DETR archive pinned in `UPSTREAM.json`. PFD-DETR is integrated into `rtdetr_pytorch/src`. Official Paddle and RT-DETRv2 directories are retained. The supplied algorithm source used Ultralytics interfaces; the release provides a corresponding implementation within the official RT-DETR framework.

New configurations use `paper_v716`. This path corrects the supplied RepC3 channel mismatch, uses class-only denoising embeddings and applies the reference Ultralytics batch-normalization, classification-loss and denoising behavior. The reference ResNet-18 configuration already has three decoder layers; it is not a six-layer model truncated for this release. The paper-compatible runtime gives bias and normalization parameters zero weight decay. Its configured training schedule has no warmup.

The earlier distribution's `legacy_official` path remains available for strict loading of its checkpoints. Checkpoints without an architecture field select that path. Its parameter layout and original optimizer behavior are preserved.

SSWR follows the stride-8 P3 output. RDPF adds a residual to the first shallow fused feature before the bottom-up path. Center-support loss is active during training. Added SSWR/RDPF residual scales start at zero. Frozen interventions do not retrain the model. Grad-CAM++ exposes the first top-down concatenation as `encoder.cam_fusion`.

The paper-compatible decoder, loss, initialization and optimizer adaptations reference Ultralytics 8.0.201 source. The integrated program uses AGPL-3.0; original Apache-2.0 source and separate dependency notices are retained. See `NOTICE` and `LICENSES`.

## Architecture statistics

The single-class baseline contains 20,082,772 trainable parameters. Full PFD-DETR contains 20,144,979. SSWR adds 11,709 and RDPF adds 50,498, for an increment of 62,207. The official headline specification of 20 M does not establish an exact count of 20,000,000. Fixed buffers and nontrainable filter coefficients are not counted as trainable parameters.

At 640 x 640, batch 1, evaluation mode, the executed convolution and linear layers require 57.8739712 GFLOPs for the baseline and 58.6272576 for the full model. The increment is 0.7532864 GFLOPs. The calculation uses THOP with only `nn.Conv2d` and `nn.Linear` hooks and two FLOPs per MAC. It excludes attention matrix products, functional MHA projections, fixed transforms, interpolation, sampling, normalization and other functional or elementwise work. It is not a comprehensive count of every operation.

`docs/PARAMETER_AUDIT.json` distinguishes trainable, frozen and stored parameter counts. `tools/profile_model.py` regenerates the profiles with the exact scope. Support-only controls retain 16,640 frozen residual parameters for state alignment; those tensors are not executed or included in their trainable totals.

## Controls and experiment coverage

The matrix contains 48 executable configurations. The release now includes WTConv, FreqFusion, P2 decoding and dual-location ordinary residual adapters, in addition to the component, gating, target, loss and sensitivity controls. `docs/CONTROLS.md` specifies the interfaces, official source locks, static counts and dependencies. `docs/CONTROL_COVERAGE.json` maps all 24 manuscript tables to their configurations or evaluation tools.

WTConv and FreqFusion require an explicit source download. The downloader checks locked hashes; model construction does not access the network. Downloaded external code is excluded from the archive. The FreqFusion adapter uses an explicitly selected PyTorch CARAFE implementation and is intended for fresh training.

The P2 initializer maps baseline P3/P4/P5 projection tensors to their correct shifted indices. Common compatible parameters are copied identically across paired variants and recorded in initialization metadata. COCO initialization records every loaded, unused or reinitialized tensor.

The new control adapters and corrected graph provide executable definitions and repeatable static statistics. They are not historical training artifacts. Original per-seed accuracy, dispersion and latency are not reproduced or regenerated by these additions. External detector recipes are listed separately in `configs/external/protocols.yaml`; training remains in each native framework. The historical MRtic-Det implementation is not included. The common evaluator accepts actual native-postprocessed COCO predictions from those frameworks.

## Heatmaps

The historical script uses Grad-CAM++ with `grad-cam==1.5.4`, direct 640 x 640 resizing, the highest-scoring 2% of queries and class scores at least 0.5. Its `all` branch actually sums classification scores because the box branch is an `elif`. The release follows that behavior. Responses are normalized within retained predicted boxes, set to zero elsewhere, normalized again over the image and displayed with detections.

The historical target is `model.model[15]`. The supplied architecture maps this index to the first top-down concatenation; the release exposes the corresponding feature by name. This structural mapping does not by itself bind historical heatmap images to archived checkpoints. Generated release images include raw arrays and configuration metadata. Their colors express relative spatial responses, not cross-model absolute activation strength.

## Validation

`docs/VALIDATION.json` records checks actually run for this archive. They include unit tests, all model configurations, real sample training/evaluation, official COCO weight loading, forward/backward controls and ONNX Runtime inference. Tests cover matched initialization, zero-residual identity, support targets, strict small-object area boundaries, operating-point matching, seed statistics and rejection of dataset-mismatched summaries.

The ONNX graph uses a fixed batch of one and fixed 640 x 640 input. Full ONNX shape/type validation and query-set agreement with PyTorch are checked. Nearly tied queries can change order, so both raw ordering differences and matched-query numerical errors are retained in the verification record.

No full-data 300-epoch training, CUDA timing, TensorRT engine validation or Jetson experiment was performed for this release. The sample smoke checkpoint is not a trained paper model. Smoke results are marked and rejected by formal experiment summaries. The CPU verification establishes software behavior, not reproduction of the paper's reported accuracy or latency.

## Data

The archive contains 200 original images and labels with derived COCO annotations, file hashes and source audits. The sample was selected from the supplied 1,304-image corpus. A file-level mapping to the manuscript's 3,200-image KFPFD dataset is not supplied. Filename families are not authenticated acquisition groups. The sample contains no fabricated occlusion or leaf-error annotations.
